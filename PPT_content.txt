### Slide 9 — USP: Engineering Decisions
**Says (bullets, ≤5, ≤8 words each):**
- Sequential Gate 0–3 routing tree
- Pattern-mirroring tiebreak for MICRO
- Mandatory auditable `reasoning` field
- Pre/post SHA hash validation
- Semantic LLM validation, not diff match

**Visual needed:** Decision-tree thumbnail from orchestrator.md Step 4 + side callout: `pre_hash == post_hash` noop guard in executor.

**Evidence:** `skills/orchestrator/orchestrator.md:66-127` (4a locatability → 4b FULL stops → 4c MICRO + pattern-mirroring test); `skills/orchestrator/orchestrator.md:161-176` (mandatory `reasoning` cites ticket evidence + locatability + pattern-mirroring); `src/agents/executor/agent.py:794-813` (`pre_hash == post_hash` noop check before LLM validation); `src/agents/executor/agent.py:933-936` (capture pre-edit hash per step); `docs/Solved_errors.md:256-266` (SHA-match/delta short-circuit replaces fragile line matching); `daily_dairy.md:232-235` (validate security property, not patch shape).

**Speaker notes:** Three decisions matter for reliability. Routing follows a strict ordered tree—not vibes—with a pattern-mirroring test so MICRO routes are defensible in the `reasoning` field. The executor captures a SHA-256 hash of each file before and after Cursor edits; if the hash didn't change, we don't pretend the fix worked. Validation asks an LLM whether the security property holds in the edited region—not whether strings match byte-for-byte.

### Slide 11 — Self-Healing Executor
**Says (bullets, ≤5, ≤8 words each):**
- Batch pass 1 — all EDIT steps
- LLM validates every edit step
- Batch pass 2 — failed steps only
- Re-validate; hard exit if still failing
- `CURSOR_MAX_EDIT_ATTEMPTS` default = 2

**Visual needed:** Flowchart exactly: EDIT batch 1 → validate all → (failures?) → EDIT batch 2 repair → validate → RuntimeError if still failed. Annotate real G-06 `retry_count: 1`.

**Evidence:** `src/agents/executor/agent.py:912-1014` (`_run_edit_batch_phase`: pass 1 apply → validate → pass 2 repair → re-validate → `raise RuntimeError`); `src/core/config.py:73-75`; `skills/executor/executor.md:35-38` (never more than `cursor_max_edit_attempts` batch passes); `evals/runs/Test3-after-Skills-adjustment/artifacts/G-06.json:214-271` (batch pass 2 repair, `retry_count: 1`, deviation `"step 2: edit required batch pass 2 repair"`).

**Speaker notes:** The executor contract is deliberately rigid.
