If I were redesigning your project today

Honestly, I think your current implementation is over-engineered.

You have

skills_loader.py

skill_registry.py

PromptBuilder.py

Three files to do something that could probably be done in one service.

I'd instead create a single component:

SkillManager

Example

prompt = SkillManager.build_prompt(
    agent="orchestrator",
    ticket=ticket,
    context=context,
)

Internally it would:

Find SKILL.md

↓

Load frontmatter

↓

Choose references

↓

Merge everything

↓

Return prompt

Now the rest of your project never knows how skills are stored.

Your orchestrator becomes

prompt = skill_manager.build_prompt(...)

response = llm.invoke(prompt)

That's all.

My recommendation for your project

Since I know your architecture (LangGraph + multiple agents + security skills + token optimization), I would not replace your system with another library.

Instead, I would reduce the amount of custom code by merging responsibilities:

Merge skills_loader.py and PromptBuilder.py into a single SkillManager.
Keep the Markdown-based skill files—they're easy to edit and version-control.
Keep progressive loading, because it's one of the features that directly supports your goal of reducing token usage.
Remove duplicate abstractions where one module exists only to call another.

There isn't a mature library today that gives you "Markdown skills + progressive disclosure + ticket-aware selection + runtime prompt assembly." That's why projects like Claude Code, Cursor, Continue.dev, Aider, and many internal agent systems all implement some version of this logic themselves. The difference is mostly how much code they hide behind one interface, not whether the logic exists.
